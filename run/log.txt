You are writing **DuckDB SQL** — NOT PostgreSQL, MySQL, or T-SQL. Key differences:

1. **IS only works with NULL**: `IS NULL` / `IS NOT NULL` / `IS DISTINCT FROM` / `IS NOT DISTINCT FROM` are the ONLY valid `IS` expressions.
   - ✅ `WHERE col != '' AND col IS NOT NULL`
   - ❌ `WHERE col IS NOT ''` ← SYNTAX ERROR
   - ❌ `WHERE col IS 'value'` ← SYNTAX ERROR

2. **Column names with brackets**: When a column name contains `[...]`, the outer `[...]` is part of the name and MUST be included in double quotes.
   - ✅ `"[Employee Master[Employee Name]]"`
   - ❌ `"Employee Master[Employee Name]"` ← missing outer brackets

3. **UNNEST for list[struct] columns**: MUST use `AS alias(var)` pattern — the `(var)` destructuring is REQUIRED. Access struct fields as `var['field']` directly.
   - ✅ `CROSS JOIN UNNEST("struct_col") AS t(rec)` then `rec['field_name']`
   - ✅ `CROSS JOIN UNNEST("struct_col") AS t1(pp)` then `pp['field_name']` — `pp` IS the struct, access directly
   - ✅ Multiple: `AS t1(r1)`, `AS t2(r2)` then `r1['field_a']`, `r2['field_b']`
   - ❌ `AS t1(pp)` then `pp.rec['field']` ← `pp` IS the struct, `.rec` is NOT a sub-field

4. **Copy names exactly**: Column names and struct field names from the listings must be copied character-for-character. Do NOT abbreviate, shorten, or reformat them.

5. **Flat columns vs struct fields**: Flat (top-level) columns are `"column_name"` directly — NOT inside any UNNEST. Struct fields are `rec['field_name']` ONLY after UNNEST.

6. **Regex operator `~` is FULL match**: Unlike PostgreSQL where `~` is partial match, DuckDB's `~` equals `regexp_full_match`. For partial match use `regexp_matches("col", 'pattern')`.
